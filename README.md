# Tank Battle

用 [three.js](https://threejs.org/) + [Tone.js](https://tonejs.github.io/) 做的瀏覽器 3D 坦克對戰小遊戲。沒有任何美術/音效素材檔案——所有模型都是程式組出來的幾何體，所有聲音跟音樂都是即時合成的。

這份 README 除了說明專案本身，也記錄了做這個專案過程中踩到、學到的東西，當作給自己以後回顧用。詳細的規格與決策歷史在 [`spec.md`](spec.md)。

## 玩法

- **WASD** 移動（坦克式：A/D 轉向、W/S 前後，不能側移）
- **滑鼠**瞄準砲塔（獨立於車身朝向）、**左鍵**或**空白鍵**開砲
- **無限生存模式**額外用 **Q** 鍵發射鎖定飛彈技能

開場選單三選一：**無限亂鬥**（敵人持續刷新）、**無限生存**（波次制 + 技能點升級系統，殺滿一波過關，每 5 波可以分配裝甲/火力點數）、**闖關模式**（設計中，尚未開放）。

## 怎麼跑起來

專案已經拆成 ES module，`import`/`export` 在 `file://` 底下會被瀏覽器擋掉，**需要起一個本地伺服器**：

```bash
python3 -m http.server
```

然後開 `http://localhost:8000/tank-battle.html`。

## 技術堆疊

- **three.js**（透過 CDN + importmap 載入）：3D 場景、坦克模型、碰撞
- **Tone.js**：所有音效與背景音樂即時合成
- **@tonejs/midi**：解析內嵌成 base64 的真實 MIDI 檔案（1812 序曲的馬賽曲主題）
- 無建置流程，純瀏覽器原生 ES module

## 這個專案學到的東西

### three.js

- **用 `Group` 組合階層式模型**：坦克 = 車身 + 砲塔（`Group`）+ 履帶等子物件，砲塔可以獨立於車身旋轉。這個模式後來也套用在飛彈模型上（彈身 + 彈頭）。
- **`Object3D.worldToLocal()` 是個好用的萬用轉換工具**：不只能拿來把滑鼠瞄準的世界座標點轉成「相對車身朝向的角度」（`atan2(-local.x, -local.z)`），後來做「方位裝甲」判定子彈是從前後左右哪個方向命中時，也是用同一招——把子彈方向轉成一個假想的世界座標點，再丟進 `worldToLocal`，等於免費做了一次座標系旋轉。同一個數學工具，兩個完全不同的功能都用得上。
- **霧效（Fog）的 `far` 距離會跟相機距離打架**：把鏡頭拉遠做「飛彈齊射全地圖俯瞰」效果時，第一版直接忘記霧效只淡出到 95 個單位，相機拉到 100 多，整張地圖直接被霧蓋成全黑畫面——只剩貼近鏡頭那一小角看得到。教訓：改動相機距離時要連動檢查霧效/裁切平面的範圍。

### 角度數學 debug：兩次真實踩到的 bug

- **砲塔瞄準反了 180 度**：一開始寫 `atan2(-local.x, -local.z) + Math.PI`，結果砲管永遠指向滑鼠的正對面。回頭用具體例子代入 Y 軸旋轉矩陣重新推導公式，才發現那個 `+ Math.PI` 是多餘的。學到的不是「這個公式怎麼寫」，而是**角度公式出錯時，代入一個具體、簡單的例子（例如「滑鼠在正右方時砲管該指向哪」）逐步驗算，比盯著公式猜哪裡錯快很多**。
- **敵人 AI 用「轉向」跟「直接位移」混著做，看起來像履帶車在滑冰**：早期版本讓敵人繞著玩家「側移」時，是直接用向量把位置平移過去，車身朝向卻是另外算的，兩者不同步，視覺上就是坦克在打滑而不是真的在轉彎前進。修法是把所有移動都改成「先轉向目標角度，朝向對了才往正前方走」——履帶車本來就不能側移，讓程式邏輯符合載具本身的物理限制，问题就消失了，不需要額外的視覺修正。

### Tone.js / 音訊

- **所有音效都能用合成器現場生出來，不用音檔**：開砲聲、爆炸聲、遊戲結束音效全部是 `MembraneSynth`／`NoiseSynth`／`MetalSynth` 這類合成器即時觸發，好處是完全不用管素材授權、檔案大小，壞處是要對音色工程有一點概念（波形、envelope 的 attack/decay/sustain/release）。
- **`Tone.Loop` / `Tone.Part` 的 `.start(time)` 不是「現在開始」，是「排定在絕對時間 time 開始」**：background music 用輪播切換三首曲子時，如果 Transport 已經跑了一段時間才呼叫 `.start(0)`，Tone.js 會把它解讀成「這個循環理論上該在絕對時間 0 就開始」——結果不是漏播開頭，就是把錯過的音符全部瞬間擠在一起爆炸播放。修法是改用相對時間 `.start()`（無參數，代表「現在」）或 `.start('+2m')`（現在起算 2 小節後），而不是絕對時間。這個坑很隱蔽，因為單獨測試「播放一次」完全不會發現，只有在「切換/重啟」的場景才會炸開。
- **MIDI 檔案可以直接內嵌成 base64，不用額外起伺服器抓檔案**：想把真實的《馬賽曲》MIDI 檔案播放出來，但 `file://` 開啟的頁面 `fetch()` 本機檔案會被瀏覽器攔下來（CORS 視本機檔案為互不信任的來源）。解法是把整個 `.mid` 檔案轉 base64、直接寫進 JS 常數裡，執行期用 `atob()` 解碼回 `ArrayBuffer` 交給 `@tonejs/midi` 解析——完全繞過網路請求這一層。事後有寫一個小腳本比對解碼後的位元組跟原始檔案是否完全一致，確保轉換沒有出錯。

### `file://` vs 真實 HTTP(S) 來源：ES module 的隱藏限制

這是這個專案裡影響最大的一個技術認知：

- Chrome 對 `<script type="module">` 的 `import` 會用 CORS 規則檢查，而每個用 `file://` 開啟的本機檔案都被視為**不透明、互不相同的來源**——所以「本機檔案 A import 本機檔案 B」在雙擊開啟時一律會被擋下來，主控台丟出 CORS 錯誤，畫面直接空白。
- 但同一份程式碼部署到 GitHub Pages 之類的真實 HTTPS 伺服器後，同網域下的所有檔案都是**同一個來源**，`import` 完全暢通無阻——問題完全出在「怎麼打開這個網頁」，不是程式碼本身有問題。
- 這個限制直接影響了架構決策：專案一開始堅持「單一 HTML 檔案、雙擊即開」，後來認真比較過拆檔案的實際好處（可維護性、git diff 可讀性、瀏覽器快取）之後，決定接受「本地開發要跑一個小伺服器」這個代價，正式把 900 多行的單一檔案拆成 7 個 ES module。這個取捨過程完整記錄在 [`spec.md` §4](spec.md#4-non-goals--constraints) 跟 §7 的決策記錄裡。

### 重構這件事：怎麼確定「我沒有把東西改壞」

拆檔案、抽 CONFIG 物件這兩次大改動，都不是「看起來對就好」，而是用了同一招驗證方式：

1. 先把原本那份程式碼的邏輯**逐字重新組裝**成跟拆分前一致的順序
2. 用程式（不是肉眼）把重組後的內容跟拆分後各檔案「依原始順序接回去」的內容做逐行 diff
3. diff 出來的差異應該**只剩下刻意做的改動**（例如某個函式被抽成獨立匯出、某個常數改成從別的檔案匯入），如果 diff 裡出現任何非預期的差異，就代表手動搬程式碼時漏東西或打錯字了

這個方法比「重構完自己看一遍覺得沒問題」可靠很多，尤其是搬動幾百行程式碼的時候，人眼很容易漏掉一行沒搬到或打錯一個變數名。

### 玩法數值設計：先問清楚公式，再動手寫

無限生存模式的波次強度曲線、技能點分配規則、方位裝甲減傷公式，一開始都只有「大概想要什麼感覺」的模糊描述。做法是先把每個模糊的地方拆成具體的二選一/三選一問題（例如「敵人變強是靠數量還是靠強度？」「技能點要不要設分配上限？」），逐一問清楚、換算成具體的數學公式（例如 `減傷 = min(0.8, 點數 × 0.05)`），寫進規格書定案之後才開始寫程式。比起「寫一版，玩起來不對再改公式」，這樣至少能保證公式本身是經過思考、彼此一致的起點。

### 「測試旗標」這個小技巧

開發過程中常常需要「這個道具先固定出現方便我測試」、「波次先縮短方便快速驗證配點畫面」這種暫時性的捷徑。做法是**明確命名成 `TESTING_XXX` 常數、加註解說明正常行為是什麼**，而不是直接把「正式數值」改掉。這樣半年後回來看程式碼，一眼就能分辨哪些是刻意的設計、哪些是還沒清掉的測試殘留——目前專案裡還留著三個這樣的旗標，清單記錄在 [`spec.md` §3](spec.md#3-known-testing-flags--temporary-state)。

## 專案結構

```
tank-battle.html          HTML 外殼（CSS、HUD 標記、importmap）
music.html                MIDI + Tone.js 播放技術的獨立原型測試頁
spec.md                   完整規格書與決策歷史
src/
  game.js                 場景/玩家/敵人/道具/飛彈/主迴圈（進入點）
  tank.js                 坦克模型工廠函式
  audio.js                音效合成器 + 背景音樂播放清單
  marseillaise-midi.js    馬賽曲 MIDI 的 base64 資料
  menu.js                 開場模式選單
  survival.js             無限生存模式：波次/技能點/裝甲/武器/飛彈數值
  config.js               集中管理的玩法可調參數
```
